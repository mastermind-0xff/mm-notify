@mmutils/notify A sticky header, to see what the messages sit above.

Notifications

The page loads only dist/esm/has-flash.js up front. The toast code and its CSS come with the first message: not loaded yet. The server sends a strict CSP (style-src 'self', Trusted Types), so nothing here may use inline styles or innerHTML.

To change how the messages look, and export the result: the design tool.

Kinds

Success and neutral close after 5 s, alert after 8 s, error after 10 s. The same kind and text again starts the one on screen over.

Your message

Behavior to try

  • Hover a message, or tab to its cross: the timer holds until both are gone.
  • An action can happen twice: both show, each with its own time.
  • On a narrow window the cross must stay inside the box.
  • and then show a message with the button in it: the message sits above the open menu (top layer). Close the other messages first: the top layer stacks by opening order, so a menu opened after them sits above them all.

    An open menu, a popover of the page.

  • Turn on "reduce motion" in your system: no animation, and messages still go away.

One after the other

With configure({ sequential: true }) one timer runs at a time, oldest message first: the next starts when the one before has closed. A message that stays until closed holds those behind it. Without it every timer runs at once.

Clear all

From three messages a button closes them all, permanent ones too. It sits below the messages, or above them in the bottom positions. configure({ clearAllFrom, clearAllLabel }) change when it comes and what it says. When the messages don't fit the window, the button is pinned to the far edge as a full row over them.

Position

A CSS-only change: these set --notify-* custom properties on :root (see page.css).

Flash across a reload

flash leaves one message in sessionStorage. After the reload the page asks hasFlash() and loads the toast code only if it says yes.
